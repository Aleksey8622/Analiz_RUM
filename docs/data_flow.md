# Поток данных Analiz_RUM

## Ежедневное обновление

Рабочие пути не хранятся в исходном коде. Они задаются локально на компьютере
в файле `analiz-rum.config.json` по примеру `analiz-rum.config.example.json`
либо переменными `ANALIZ_RUM_SOURCE_FOLDER` и `ANALIZ_RUM_DATABASE_FOLDER`.

Файл `analiz-rum.config.json` исключён из Git и не должен передаваться между
компьютерами вместе с исходным кодом.

1. Пользователь входит в локальное приложение.
2. Выбирает «Создать обновление» и загружает SAP-файлы.
3. Приложение определяет отчёт по имени и заголовкам, проверяет типы и показывает результат проверки.
4. Все корректные файлы записываются в `analiz_rum.db` одной транзакцией.
5. Если любой обязательный файл или строка не прошли проверку, обновление не становится активным.
6. После успешной записи экраны читают последние завершённые снимки через SQLite views.

## Расчёты запасов

- Производство: `SUM(СвобИспользЗпс)` с группировкой по `Номер материала`.
- Склад: `SUM(Количество)` с группировкой по `Продукт`; все складские места одного продукта суммируются.
- Запас в блоке: `SUM(Количество)` с группировкой по `Продукт`.
- Общий доступный остаток: склад + производство. Блок хранится и показывается отдельно.

## Поставки и корректировки

- Активные поставки содержат строки с `Остаток поставки > 0`, не исключённые вручную.
- Строка с нулевым остатком показывается на странице «Поставки-корректировки» как завершённая.
- Нецелесообразный остаток меньше паллетной кратности переносится туда ручным действием пользователя с причиной.
- Исходная строка SAP не изменяется; решение хранится отдельно в `supply_corrections`, поэтому доступно для аудита и отмены.

## Прогноз упаковки через разузловку

Расчёт требует связать прогноз выпуска GP с компонентами разузловки:

`прогноз компонента в день = SUM(прогноз GP в день × расход компонента на единицу GP)`.

Для реализации нужен пример источника прогноза GP и точное значение базы количества в разузловке (на 1, 1000 или иной объём GP).
