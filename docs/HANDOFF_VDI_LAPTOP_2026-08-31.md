## Что произошло и что уже удалось

1. Команды `npm.cmd run start:work` и `npm.cmd run finish:work` дали `Missing script`: в показанном package.json таких scripts не было. Эти попытки не запускали синхронизацию.
2. Существующие start-work.cmd/finish-work.cmd жёстко ссылались на диск Z: VDI.
3. В обоих CMD вызов `npm.cmd run build` был без `call`, поэтому управление могло не возвращаться для следующего шага.
4. Обошли эти CMD: запустили сборку и существующий publish последовательно из PowerShell с проверкой кодов завершения.
5. Пользователь подтвердил: версия опубликована, изменено 15 файлов. НЕ пересоздавать Excel и НЕ сбрасывать baseline.

Подтверждённый способ публикации из текущей папки проекта:

```powershell
& {
    $ErrorActionPreference = 'Stop'
    if (!(Test-Path -LiteralPath '.\scripts\work-sync.cjs')) {
        throw 'Не найден механизм синхронизации. Ничего не опубликовано.'
    }
    npm.cmd run build
    if ($LASTEXITCODE -ne 0) {
        throw 'Сборка не прошла. Публикация не запускалась.'
    }
    node .\scripts\work-sync.cjs publish
    if ($LASTEXITCODE -ne 0) {
        throw 'Публикация не завершилась успешно. Пришли сообщение выше этой строки.'
    }
}
```

Предусловия: Node/npm доступны в текущем терминале, приложение и Excel-файл синхронизации закрыты, текущая папка — именно проект. Команда не чинит PATH после перезагрузки. При ошибке не объявлять публикацию успешной.

Не начинать с установки нового sync-движка. Сначала использовать и проверить существующий механизм.

1. Открыть реальную папку проекта ноутбука в VS Code, не путь VDI. Ранее пользователь работал в `C:\Users\Aleksey.Rudnev\Desktop\Analysis Room\Analysis Room`, но существование проверить.
2. Прочитать package.json, scripts/work-sync.cjs, start-work.cmd и finish-work.cmd, локальную конфигурацию синхронизации и реальную цель рабочего ярлыка. Проверить Node/npm. Не просить присылать весь Excel, базу или секреты.
3. Сделать резервную копию локального проекта без node_modules, а также локальной БД и состояния синхронизации до изменения файлов. Не писать резервную копию поверх исходников.
4. Проверить, что конфигурация указывает на ту же существующую книгу Excel и состояние установленной версии не сброшено. Закрыть приложение и книгу. Сравнить локальную версию с последней опубликованной.
5. Если есть неопубликованные изменения или конфликт — остановиться и сохранить их, а не перезаписывать принудительно. Не публиковать старую версию ноутбука поверх новых обновлений VDI.
6. Если механизм совместим и конфликтов нет, получить обновления существующим `node .\scripts\work-sync.cjs sync`. После успешного sync — сборка. Проверять код завершения каждого шага; при ошибке не переходить к запуску.
7. Запускать через проверенный локальный ярлык/launcher ноутбука. НЕ переносить жёсткие пути Z: или launcher VDI вслепую. На VDI Electron с сетевого диска давал GPU error 18, а локальная копия Electron через существующий launcher работала. Не добавлять очередной набор GPU-флагов без диагностики.

9. Затем минимально исправить переносимые start/finish команды: путь относительно CMD, корректный возврат после вызова npm.cmd, обработка ошибок, реальный launcher конкретного устройства. Две команды должны быть подтверждены на обоих устройствах, а не только добавлены в package.json.

Пользователю дать ОДИН цельный PowerShell-блок после проверки фактических файлов ноутбука. Не выдавать заранее универсальный код, предполагающий неизвестные пути и состояние.

## Что есть на VDI по последнему обсуждению

- Оформление DELEKTO; анимация букв восстановлена. Пиксельный шрифт значительно улучшился после включения ClearType в VDI.
- Обечайки отдельно от общего анализа упаковки; формат и клиент из текущего справочника.
- Страницы остатков склада, цеха и запаса в блоке скрыты из навигации, но импорт и данные должны сохраняться.
- Историческая загрузка: только выбранная дата из архива, не сканирование всего архива.
- Текущий справочник берётся из SAP_Reports даже при просмотре прошлой даты. Позиции, исключённые из текущего активного справочника, не восстанавливаются только ради истории.
- Для остатков суммируются ВСЕ строки по коду материала/PLU: склад по всем местам, производство по всем цехам. Общий остаток = склад + производство; запас в блоке отдельно.
- Исправлялась трактовка чисел Excel: 2 места × 7200 = 14 400, а не 14,4. Дробная часть реального остатка сохраняется. Контрольные примеры пользователя: склад 111 850 по восьми местам; производство 170 000,47 по шести строкам.
- Прогнозы, МТЗ и прочие расчёты не считать полностью реализованными только потому, что подтянулись остатки.

## Код приложения и база данных — разные вещи

Чтобы на ноутбуке появились актуальные остатки, проверить его реальный путь к источнику Excel, доступность общей папки, выбранную дату и обновление данных. Выяснить, общая ли база или локальная, прежде чем предпринимать действия. Не заменять и не удалять базу.
